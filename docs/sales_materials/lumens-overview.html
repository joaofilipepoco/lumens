Lumens04 / 09
The developer change

Less code. Better answers.

Before

// custom tracing, tags, error paths,
// metrics and vendor correlation...
Span span = tracer.startSpan("payment-" + id);
span.setAttribute("customer", customerId);
...

With Lumens

// standard HTTP span is already automatic
operations.observe("payment.authorize", op -> {
  var result = authorize();
  op.setOutcome(result.approved()
      ? "approved" : "declined");
  return result;
});

No automatic arguments, return values, payloads, credentials, or arbitrary headers.

Lumens05 / 09
Business-aware by default

Not every non-success
is a technical error.

Technical failure

ERROR with exception type and trace context. The service failed to execute correctly.

Expected business outcome

declined, unavailable, or rejected are observed as business signals without falsely marking the span as an error.

“A payment declined” is often the answer the business needs, not an outage.

Registered events, bounded outcomes, and shared contracts make that answer consistent across services.
